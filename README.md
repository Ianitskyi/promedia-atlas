# Атлас Медіа

Інтерактивний каталог реєстру Нацради станом на 01.08.2026. Карта регіонів, пошук, фільтри, картки медіа, портфелі реєстрантів та довідка про реєстрацію.

Окремі публічні сторінки медіабрендів доступні за `/media/<brand-id>`. Профілі розкладено в невеликі файли `public/data/brand-buckets/`, щоб не завантажувати весь реєстр на сторінці бренду. Автоматичне об’єднання дозволено лише для однакової нормалізованої назви в одного реєстранта; неоднозначні випадки задаються і документуються в `data/brand-overrides.json`. Новини завантажуються з `news.promedia.report` за ідентифікатором бренду та, для однозначних збігів, за наявним ідентифікатором каталогу спільнот.

Google Analytics використовує спільний для сайтів ПроМедіа ідентифікатор `G-D8TM22QR9R` у кореневому layout, тому охоплює каталог і сторінки брендів.

## Мови

Сайт має три версії: українську (`/`), англійську (`/en`) і кримськотатарську латинкою (`/crh`). Компоненти пишуть пари `tr('укр', 'English')`; кримськотатарський переклад береться зі словника `CRH` у `lib/i18n.ts` за англійським текстом (без перекладу показується український текст). Там само — адреси сусідніх сайтів мережі для кожної мови, щоб перемикання й навігація зберігали мову.

Правила кримськотатарського перекладу (джерела, обов'язковий глосарій, абетка, самоперевірка) — єдині для всієї мережі: [CRIMEAN_TATAR_TRANSLATION_RULES.md](https://github.com/ianitskyi/promedia-news/blob/main/docs/CRIMEAN_TATAR_TRANSLATION_RULES.md). Тут їх не дублюємо; зміни вносимо спершу туди.

## Оновлення даних та історія

Atlas зберігає незмінні знімки оприлюдненого реєстру у `public/data/history/snapshots/`. Поточний каталог — останній знімок, а `public/data/history/index.json` містить порівняння за ідентифікатором медіа.

- «З’явився у знімку» означає, що ідентифікатор є у новому файлі й не був у попередньому; це не дата реєстрації.
- «Відсутній у знімку» означає, що ідентифікатора немає в новому оприлюдненому файлі. Це **не** є твердженням про скасування реєстрації. Такий статус можна назвати скасуванням лише після звірки з рішенням Нацради.
- «Змінено відомості» порівнює назву, реєстранта, категорії, місцезнаходження, технології, контакти й записи джерела. Номери рядків та їх порядок ігноруються.

Імпортер читає лише значення клітинок, не виконує формули або інструкції з файлу. Він перевіряє дату й структуру обох аркушів. `scripts/registry_history.py` відмовляється перезаписувати знімок, а також зупиняє оновлення при підозріло великій зміні кількості записів.

Планова GitHub Action `Update registry monthly` запускається 12-го числа кожного місяця о 07:00 UTC і її можна запустити вручну. Вона знаходить на сторінці Нацради найновіший датований `.xlsx`, звіряє джерело, будує кандидат, запускає перевірки, зберігає знімок та надсилає валідовану зміну в `main`. Якщо файл не змінився, Action не створює коміту й не розгортає сайт. За потреби її можна перевести на раз на два місяці, змінивши cron у `.github/workflows/update-registry.yml`.

`scripts/build-registry-trends.mjs` після кожного оновлення перераховує `public/data/history/trends.json` — компактний підсумок (перший і останній знімок, кумулятивні появи/зникнення/зміни, найбільші зрослі й скорочені види діяльності та області, підсумок штрафів). Блок «Підсумок тенденцій» на сторінці `/analytics/history` читає лише цей файл, не повні знімки.

Перевірити весь процес локально: `python scripts/test_registry_history.py`, `node scripts/verify-data.mjs`, `node scripts/verify-brands.mjs`, `node scripts/verify-analytics.mjs`, `node scripts/verify-history.mjs`.

Повідомлення про штрафи зберігаються окремо в `public/data/regulatory-actions.json`. У публічному інтерфейсі вони мають першоджерело, суму, дату, підставу та спосіб прив’язки до реєстрації. Автоматично публікувати такі збіги небезпечно: одна новина може стосуватися незареєстрованого суб’єкта, кількох медіа або припису замість штрафу. Тому оновлення реєстру автоматичне, а додавання санкцій — коротка редакторська перевірка первинного рішення чи офіційного повідомлення.

Джерело: https://webportal.nrada.gov.ua/derzhavnyj-reyestr-sub-yektiv-informatsijnoyi-diyalnosti-u-sferi-telebachennya-i-radiomovlennya/

Унікальність медіа визначено ідентифікатором. Реєстрантів об’єднано за кодом, за відсутності коду — за найменуванням. Податкові номери фізичних осіб і контактні email не експортуються. Внутрішній ключ реєстранта — хеш. Методологію викладено також на сайті.

Контури областей запозичено з наявного проєкту ПроМедіа `promedia-communities/img/ukraine-oblasts.svg`. Імпортер очікує цей сусідній проєкт; уже підготовлений `app/map-paths.json` входить до репозиторію. Карта не є картою покриття сигналом. Геокодування міст не виконано.

## Публікація

Код зберігається у GitHub. Після кожного пушу до `main` GitHub Actions збирає
проєкт і публікує його у Cloudflare Workers. У репозиторії потрібно додати два
GitHub Actions secrets: `CLOUDFLARE_API_TOKEN` (з правами Workers Scripts: Edit
та Zone: Read/Edit для `promedia.report`) і `CLOUDFLARE_ACCOUNT_ID`. DNS-запис
`atlas.promedia.report` має бути проксійований через Cloudflare. Після першого
запуску workflow у Cloudflare потрібно призначити маршруту
`atlas.promedia.report/*` Worker `promedia-atlas`; надалі кожен пуш до `main`
оновлюватиме його автоматично.

Довідку перевірено 07.09.2026 за офіційними сторінками Нацради, доступними через пошуковий індекс. Пряме отримання частини сторінок повертало 502. Сума збору 2026 року — 3 328 грн; форми змінено рішенням № 1937 від 23.07.2026. Посилання на першоджерела розміщено в довідці. Перед щорічним оновленням перевіряти суму, чинний порядок і канал подання.
